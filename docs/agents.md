# Как работают участники и агенты

Пять равноправных участников, у каждого свой Claude Code (тариф Pro). Координатора и
оркестратора нет: общий список задач — GitHub Issues, общая точка стыковки — контракты
(`docs/contracts.md`), общий судья — `tools/eval` на holdout (D-012, D-013).

## Одна сессия — одна issue — один worktree

```bash
gh issue list --search 'no:assignee label:area:core-slip'   # свободные задачи области
gh issue edit 12 --add-assignee @me                         # взял — видно всем сразу
claude -w 12-slip-detector                                  # сессия в .claude/worktrees/12-slip-detector
```

Перед тем как взять: `session-context.sh` в начале сессии печатает мои issues и занятые
области. Если `area:` уже у кого-то в работе, эту issue не берём, берём другую. Когда все
зависимости из «Зависит от #…» ещё не в `main`, работа идёт на заглушке, и в PR это
помечено.

Основная сессия участника и есть исполнитель, отдельный `builder` для этого не нужен.
Модель по умолчанию `sonnet` (`.claude/settings.json`). На математику модели и фильтра
(вывод уравнений, якобианы EKF, наблюдаемость, разбор, почему фильтр расходится) участник
вручную переключается на `opus` командой `/model opus`, а когда вывод закончен, возвращается на `sonnet`.

## Субагенты — по запросу, не на каждую задачу

Лимиты Pro общие на сессию и субагентов: каждый субагент начинает с нуля и заново читает
контекст. Поэтому субагента зовут, когда нужен **свежий взгляд или изоляция**, а не для
того, чтобы «было по процессу».

| Роль | Модель | Когда звать | Видит и может | Возвращает |
|---|---|---|---|---|
| `builder` | sonnet | отдать issue целиком, пока сам занят другой | свой worktree; полный набор инструментов; контракт и зависимости не меняет | PR, отчёт с командами и таблицей «было → стало» |
| `reviewer` | sonnet | PR трогает контракт, `params.yaml`, формат метрик, ядро оценщика (estimator/slip/dynamics) | только diff против `origin/main`; ничего не правит | вердикт `merge` / `доработать` / `человеку` с `файл:строка` |
| `evaluator` | sonnet | таблица «было → стало» для PR; чекпоинт; стенд жюри перед сдачей | `tools/eval`, `docker/jury-stand.sh`; пишет только в `docs/verification/` | таблицы с командами и commit |
| `scribe` | sonnet | документы сдачи, README; документ разошёлся с кодом | worktree; выполняет команды, которые описывает | документы, список `TBD` |
| `jury` | opus | перед чекпоинтом и сдачей; режим 2 — репетиция вопросов питча | только артефакты; ничего не правит | баллы 30/35/20/15 и питч 10/12/8, топ-5 действий; или 15 вопросов |

Запуск вручную: «Запусти reviewer на PR #17», «evaluator: сравни ветку
worktree-12-slip-detector с origin/main на holdout», «jury: режим 2». Определения —
`.claude/agents/*.md`. Правила проекта агенты получают из `CLAUDE.md` сами, поэтому в
промпте роли только то, что её отличает.

## Что нужно знать

- Субагент запускается в каталоге сессии. Если сессия открыта через `claude -w`, это уже
  worktree issue. Если в основной копии, путь worktree передаётся в бриф.
- `reviewer`, `jury` файлы не правят. `evaluator` пишет только `docs/verification/`.
- Хук `SubagentStop` (`check-worktrees.sh`) проверяет секреты во всех worktree после
  каждого субагента.
- Изменение контракта, новая зависимость, сокращение объёма условий решаются не агентами
  между собой: их выносят людям через PR с апрувом потребителей.

## Точки сборки команды

Синхронных созвонов-оркестраторов нет. Есть две общие отметки в день (время — в плане):
`main` зелёный, `tools/eval` на holdout по `main` записан в `docs/verification/`, итог и
блокеры — две-три строки в `HANDOFF.md`.
