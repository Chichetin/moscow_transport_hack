## Что действительно запускалось

- 26 bag нашего **holdout**: штатное наше ядро и адаптеры ядер всех пяти соперников.
- 51 bag **train**: baseline и два экспериментальных варианта нашего pipeline.
- 6 фиксированных train-bag: четыре стресс-сценария для трёх вариантов, 72 проверки.

  Это сравнение вычислительных ядер с явно описанными адаптациями, не прогноз баллов жюри.

## Результаты скорости

Медиана RMSE по 26 bag, м/с; меньше лучше. В основной колонке каждый алгоритм
сравнивается на **одних и тех же точках** внутри bag: пересечение доступных совпадений
всех восьми вариантов. Медиана покрытия этого пересечения — 90,10% эталона.
Это не среднее всех отсчётов всех bag. Совпадение с эталоном — ближайшая точка ±0,05 с.

| Вариант | RMSE на общих точках | Точнее нас на bag | Покрытие собственных выходов |
|---|---:|---:|---:|
| **Наш main** | **0,03497** | — | 99,97% |
| TellSamm / LCM, общая калибровка | 0,04319 | 7/26 | 99,95% |
| LCM, калибровка вагона из имени bag | 0,04373 | 5/26 | 99,95% |
| b1ank37 / mttex | 0,04689 | 4/26 | 90,14% |
| ilushenssss, адаптер ядра | 0,05651 | 2/26 | 99,97% |
| ktoyart, дополнительно исправленные единицы | 0,29060 | — | 90,10% |
| Ange1ika, адаптер C++ DualEkf | 0,79336 | 0/26 | 99,97% |
| ktoyart, оригинальные входные единицы | 16,04224 | 0/26 | 90,10% |

Падений в этом запуске нет. Это не доказывает отсутствие ошибок в нативных нодах.
Наш штатный RMSE на всех собственных совпадениях — 0,03470 м/с.
LCM выигрывает, например, на `30618_2050d396`: 0,04464 → 0,03660 м/с (примерно 18%).
mttex на `30618_33bec73f`: 0,05267 → 0,04205 м/с. Их преимущества локальны;
разбирать эти режимы полезнее, чем заменять весь наш фильтр.

Для положения сопоставлены только наше ядро и LCM с картой. Наш along-track RMSE —
2,353 м, LCM — 9,028 м после фиксированного переноса base_link к proxy GNSS master
на −9,873 м по касательной. Без переноса LCM даёт 14,876 м. Наш drift — 0,0192%,
LCM после переноса — 0,6849%. Это медианы разных метрик, не взаимозаменяемые оценки.
Карта, высота и геометрия антенны конкурента добавляют ограничения такому сравнению.

## Ограничения, влияющие на вывод

1. LCM использует опубликованную карту/калибровку, обученную с пересечением нашего
   holdout. Это сравнение фиксированных артефактов, не независимая оценка обобщения конкурента.
2. Входы читаются в порядке доставки записи; будущий GNSS не подаётся оценщикам.
   Инициализация LCM сохраняет ограничения первых входов/окна. Номер вагона из имени bag
   в варианте pertram — дополнительная информация вне контракта ноды.
3. mttex/ktoyart: исполняются исходные callbacks, публикации перехвачены;
   штатные ROS-таймеры не воспроизведены. У mttex точка оценки берётся на front callback,
   поэтому меньшая полнота и stamp здесь не оценка нативной публикации.
4. ktoyart: небезопасный внешний pickle карты не загружался; использован прямолинейный
   fallback, не меняющий уравнений скорости. Положение этого варианта не сравнивается.
5. ilush: две скорости, нормированная команда, без карты, шаг по событию вместо 50 Гц.
   Ange: исходный C++ DualEkf, среднее свежих колёс, адаптация массы разрешена;
   отсутствуют нативный таймер 100 Гц и ограничения ROS-обёртки. Это результаты адаптаций.
6. Время выполнения из JSON — время офлайн-адаптера, не latency ROS и не итог на стенде жюри.
7. Эксперименты остановлены после завершённых прогонов по просьбе пользователя.
   Следующий обязательный шаг для кандидатов — исправление регрессий и holdout, а не merge.
