# #59: фильтр скорости против min/max-селектора тележек

- Код: `main` @ `e028d56` + ветка `worktree-59-selector`; селектор — `estimator/selector.py`
  (`WheelSelector`), в `pipeline` не подключён.
- Машина: `Linux 6.18.44-fc-v42 x86_64`, 4 ядра; данные — 122 bag релиза `dataset-2026-09-25`.
- Команда:

```bash
.venv/bin/python tools/eval/exp_selector.py --split holdout --jobs 4
```

Скрипт гоняет один и тот же `pipeline.Odometry` трижды: со своим фильтром скорости (D-057),
с `WheelSelector` на месте фильтра и с контролем «всегда среднее доверенных тележек»
(тот же селектор с нулевым ускорением модели). Метрики — `tools/eval` (контракт §4).

Селектор: тяга по модели привода (`accel_model > 0`) — меньшая из доверенных тележек
(буксующая завышает), `accel_model < 0` — большая (юзящая занижает), среднее — только при
`accel_model` ровно 0. Модель с сопротивлением Дэвиса ровно 0 практически не даёт (ревью:
на `30639_584b6e32` из 44 904 вызовов — 0), поэтому на выбеге тоже берётся большая тележка;
**проверен селектор «min на тяге, max на выбеге и торможении»**, вариант с мёртвой зоной по
`accel_model` не проверялся. Доверие — только порог: 0 исключает тележку, любое положительное
считается полностью. Тележка, молчащая дольше `input.stale_timeout_s`, не участвует; обе
молчат — скорость продолжается по модели привода.

## Вывод

Гипотеза #59 («селектор не хуже фильтра») не подтвердилась. Фильтр лучше по всем
медианам и по скорости на каждом из 4 bag с расхождением тележек. Селектор по скорости хуже даже
простого среднего (+9 % RMSE, bias разгона и торможения больше), по положению чуть лучше
среднего (drift 0.0245 против 0.0278). В `pipeline` остаётся фильтр; селектор не
подключается и не становится запасным режимом (D-059).
