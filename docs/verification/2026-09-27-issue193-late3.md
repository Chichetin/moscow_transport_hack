## Методика и область вывода

Один полный replay исходного примера организаторов `30618_88aea4d9`, rate 1,
полный пакет сообщений репозитория, неизменённый checker организаторов.
Контейнер: ROS 2 Humble, 2 CPU, 512 МиБ, без сети, непривилегированный пользователь.
Bag монтировался только для чтения. Сборка из архива завершилась с exit 0.
Сначала запущен checker и наблюдатель frame_id, затем:

```bash
ros2 bag play /bag --rate 1.0
# в параллельном процессе через 3 секунды после вызова player:
ros2 launch tram_odometry odometry.launch.py
```

После завершения player выдерживаются четыре секунды для финальной таблицы.
Checker, launch и наблюдатель останавливаются отдельно; коды каждого процесса
сохраняются. Задержка считается между вызовами процессов, не между первым
сообщением bag и готовностью подписок.

Это известный пример судьи, ранее использованный при разработке, не слепая
оценка. Новых параметров не подбирали; train/holdout и sealed-каталоги #154
в этом прогоне не использовались. В исходном bag GNSS присутствует почти
всю запись. Поэтому успешный late3 не доказывает успех при пропущенном
коротком начальном GNSS и не закрывает #201.
