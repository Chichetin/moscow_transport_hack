## Что увидели

Организаторы 27.09 опубликовали tf антенн в `base_link`: master x = −9,873, rover x = +2,563,
обе y = 0, z = 3,0 м; `base_link` — ось вращения передней тележки, по высоте — точка касания
колеса и рельса; между осями тележек 7,55 м. Данные с tf согласны: база master → rover по
парам статуса 2 с разницей stamp ≤ 0,06 с на 26 bag holdout — медиана 12,43–12,44 м
(= 9,873 + 2,563), разность высот антенн — медиана по bag от −0,21 до +0,08 м.

`/result/position` публиковал трек антенны master (карта построена по master, высота — высота
антенны) с `child_frame_id = base_link`, то есть точку на 9,873 м позади и 3,0 м выше
объявленной. README судьи: положение «сравнивается покомпонентно (x/y/z) и по 3D-расстоянию».

## Что сделано

- `PathTracker.advance` — точка на `position.base_ahead_m` = 9,873 м дальше по дуге карты
  (с переходами веток и развилками) и на `position.antenna_height_m` = 3,0 м ниже. Якорь,
  привязка к остановкам, масштаб колеса, выбор боковой ветки — по-прежнему в дуге master.
  За тупиком карты выход продолжается по касательной не дальше `base_ahead_m`: карта кончается
  там, где стоял master при записи, рельс под осью тележки есть ещё на 9,873 м.
- `tools/eval`: эталон по умолчанию — `base_link` (`--ref-point master` — прежний). При
  rover-fix того же момента (±0,06 с) с базой 12,436 ± 0,5 м — точка на прямой master → rover
  в 9,873 м от master (жёсткий вагон); без пары — по курсу ближайшей пары, пока трамвай проехал
  ≤ 1 м; иначе — на 9,873 м дуги дальше по треку master. Высота — минус 3,0 м. Начало frame —
  fix master, как было. В `metrics.json` — ключ `ref_point`.

Сверка двух способов эталона на holdout: «трек вперёд» отличается от пары master → rover на
медиане 0,07–0,89 м по bag, но на петлях у конца прогона — до 4,6 м (хорда против дуги),
поэтому пара главнее.

## Holdout 2×2

Медианы по 26 bag holdout (17 bag 30618 — отдельно: проверять будут только 30618). Скрипт
гоняет `tram_eval.bag.evaluate_bag` на одних и тех же сообщениях, меняя точку выхода
(`base_ahead_m`/`antenna_height_m` = 0 → master) и `ref_point`.

| выход → эталон | bag | speed_rmse | along_rmse | pos3d_rmse | drift_pct |
|---|---|---|---|---|---|
| master → master (как `main`) | все | 0,0345 | 2,359 | 2,750 | 0,0181 |
| master → master | 30618 | 0,0292 | 2,102 | 2,478 | 0,0129 |
| **base_link → base_link** | все | 0,0345 | **2,331** | **2,696** | **0,0140** |
| **base_link → base_link** | 30618 | 0,0292 | 2,122 | **2,371** | **0,0098** |
| base_link → master | все | 0,0345 | 9,316 | 10,307 | 0,1809 |
| master → base_link | все | 0,0345 | 10,789 | 11,527 | 0,1996 |

Точка выхода должна совпасть с точкой эталона судьи: при совпадении `base_link` не хуже
master (along +0,02 м на 30618 при −0,11 м pos3d и −0,003 п.п. drift), при несовпадении в любую
сторону — ~10 м along и pos3d. За `base_link` говорят опубликованный tf и `child_frame_id`.
Точка эталона судьи и начало его frame не подтверждены — вопрос в Q1 (#23); откат — оба ключа
`0` в `params.yaml`.
