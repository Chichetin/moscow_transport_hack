(решение фильтра теперь D-094, D-090 оставлено за #179). База — чистый
`origin/main` 255b74b; ветка — `worktree-math-review-2` после merge. На обеих
ветках использованы одни 26 bag holdout, одинаковая карта и `params.yaml`.

```bash

  --split holdout --jobs 8 --stress --compare <base>/metrics.json
python -m pytest -q
```

Полный pytest прошёл. Holdout: speed RMSE +0,157%, along RMSE −0,191%,
drift −0,407%, pos3d RMSE −0,311%; D-012 «главные метрики не хуже»,
падений, NaN и расхождений stamp нет.

Стресс (медиана по доступным bag): `gap_both_30` добавка к пику ошибки скорости
1,245 → 1,129 м/с, добавка к пику ошибки позиции 10,476 → 8,051 м;
`freeze` добавка скорости 1,319 → 0,990 м/с, `noise` 0,357 → 0,345 м/с.
Но абсолютный пик ошибки позиции в `gap_both_30` вырос 15,385 → 19,133 м;
число bag без восстановления позиции выросло с 4 до 6.

Регрессия не случайна: на `30618_67b89902` перед паузой было выучено
`b ≈ +0,27 м/с²`, компенсирующее отрицательную ошибку модели торможения.
В базе `b` сохраняется, и к концу паузы скорость 6,67 м/с при эталоне
5,44 м/с. В ветке `b` затухает до нуля, скорость состояния доходит до нуля
при том же эталоне; пик добавочной ошибки скорости этого bag 1,38 →
7,18 м/с, позиции 12,91 → 111,62 м. Без колёс оценить, является ли
выученное `b` реальным уклоном/ошибкой таблицы или случайным шумом,
невозможно. Поэтому PR остаётся черновиком: медианные улучшения подтверждены,
но хвост ошибок на holdout требует отдельного решения до merge.
