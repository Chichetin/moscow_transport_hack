# Разбор архитектуры одометрии (#45)

Разбор архитектуры от 25.09 (`origin/main` на момент разбора — `4d9840b`), перенесён в
markdown из черновика того же дня. Часть выводов — про само решение, проверена зондом
`tools/survey/probe_route.py` на bag `dataset/data`; часть — про процесс команды, свёрнута
до итога и ссылки на решение (`docs/decisions.md`). Числа раздела «Что показали данные» —
из вывода зонда в этой сессии 25.09, не из черновика: часть чисел в черновике устарела
после исправления `splits.yaml` и дублей. У каждой рекомендации — статус на сегодня
(25.09, сверка по `docs/decisions.md` и `gh issue list --state all`).

## Главное

1. Положение (35 баллов) упиралось в масштаб колеса: в окне GNSS трамвай не едет ни в
   одном из 97 bag, значит калибровка «если едет» (`docs/decisions.md`, D-005) не
   срабатывает никогда. Решение — привязка пути `s` к местам остановок из карты и оценка
   масштаба между остановками. **Сделано**: D-034 (#56, closed), holdout along RMSE
   4,67 → 2,61 м (−44 %), drift 0,343 % → 0,028 %.
2. Стык eval и ноды — два риска исказить таблицы ещё до модели: eval сортировал бы вход
   не так, как `ros2 bag play`, и PyYAML читал бы три id bag из `splits.yaml` как числа.
   **Сделано**: eval идёт в порядке записи bag (D-020), `splits.yaml` — id в кавычках
   (D-020, было #34, closed); PyYAML-ловушка подтверждена в этой сессии командой ниже.
3. Окно GNSS резалось в двух местах. **Сделано**: единственная точка отсечения —
   `Preprocessor` (D-031); тест «GNSS после окна не меняет выход» есть на уровне модулей
   (`test_bag.py`, `test_odometry_node.py`), но сквозной bit-for-bit тест `pipeline.step`
   для ноды и eval вместе — **открытая issue #57**, не сделано.
4. Высота вдоль маршрута меняется заметно, а ранний контракт публиковал `z = 0`.
   **Сделано**: колонка `z_m` в `route.csv` (D-024, было #39, closed); диапазон
   подтверждён в этой сессии — 27,7 м (см. ниже), что ближе к числу D-024 (28 м), чем к
   черновой оценке 37 м из старого разбора — она снята как неподтверждённая.
5. Десять подписок Claude Code на пятерых — вопрос внимания людей и числа слияний в
   `main`, не токенов. **Сделано** как процесс, без деталей чужих репозиториев: вторая
   дорожка каждого участника (evaluator/reviewer/jury на свои PR, ночные прогоны) записана
   в D-016, D-026; координация без оркестратора — D-013.

## Проверки и инфраструктура

Из разбора приняты и записаны решениями: чистая сборка из `git archive HEAD` и раскладки
жюри без сети (D-025, `tools/submission/jury_layouts.sh`), CI на pytest/`colcon
build`/`colcon test` и раскладки жюри на каждый PR и `main` (D-026,

`ps`/`docker stats` (D-023, `tools/stand/sampler.py`).

Не принято или не сделано:

- Теги `cp0`/`cp1`/`known-good`/`submit-final` — в репозитории тегов нет
  (`git for-each-ref refs/tags` — пусто).
- `docs/robustness.md` как отдельная матрица «сбой → обнаружение → реакция →
  восстановление → тест» — файла нет; часть покрыта текстом в `docs/accuracy.md` §5 и
  решениями D-027 (проскальзывание), D-031 (выбросы, дыры) без единой таблицы.
- Тест, разбирающий `.msg` и сверяющий поля сообщений без сборки ROS, — не найден.
- «Что число не доказывает» как явная оговорка при каждой цифре — не оформлено отдельно;
  близкое по смыслу есть в `docs/roadmap.md` («Известные физические ограничения»: карта
  привязывает только известную линию, GNSS вне первых секунд недоступен), но не как
  колонка у каждого числа `docs/accuracy.md`.
- Двойной прогон стенда на одном commit ради разброса латентности — не встречен в
  `docs/verification/`; текущий отчёт стенда (D-038) — по одному прогону на три bag.

## Процесс

Из разбора чужих репозиториев (ozon, pochta, Sber, MAX_GOATed_messenger) в проект попали
только итоги, без деталей чужого кода: вторая дорожка каждого участника на проверки,
стенд и ночные прогоны, без отдельной роли интегратора (D-016, D-026); координация через
GitHub Issues и `area:` без оркестратора (D-013); слияние только по улучшению holdout-метрики
(D-012); `reviewer` на PR с кодом — `opus` (D-026). Подробности — `docs/agents.md`.

## Расхождения с решениями

По правилу проекта расхождение данных с записанными решениями выносится людям, не
переписывается молча.

- **D-005** («калибровка масштаба колеса, если трамвай едет, в окне GNSS») — в окне
  трамвай не едет ни в одном из 97 bag (пункт 14). Текст решения не обновлён; на практике
  калибровка масштаба теперь идёт офлайн (D-033) и онлайн между остановками (D-034), ветка
  «если едет» не используется нигде в коде.
- **D-009** («масштабы колёс — медленные состояния фильтра») — оценщик #11 (EKF) ещё не
  реализован (issue #11, open), масштаб сейчас живёт в `PathTracker` как регрессия по
  остановкам (D-034), не как состояние фильтра. Возможное расхождение снимется или
  подтвердится при реализации #11.
