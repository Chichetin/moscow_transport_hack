## Что уже выяснено — не повторяй ошибочные направления

- Пауза/откат timestamp сами по себе не отличают новый bag от сбоя датчика внутри текущего. GNSS не должен служить подтверждением нового прогона и открывать себе новое окно.
- В проверенных образах Humble `rclpy` callback получает только сообщение. Низкоуровневые metadata содержат transport timestamps, но не publisher GID. Граф показывает endpoint GID, однако синтетический ROS-прогон доставил старые сообщения из очереди уже после появления в графе только нового издателя. Автосброс по снимку графа небезопасен.
- GID в `rclcpp` относится к endpoint, не гарантированному run ID или группе топиков. Переход на C++ перед сдачей не является доказанным минимальным решением.
- Без полученного начального GNSS или разрешённой исходной позиции нельзя гарантировать абсолютный якорь выбором одной из конечных по скалярным колёсам. Не включай эту эвристику в #200.
