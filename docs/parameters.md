# Параметры и допущения

Источник всех значений — [`params.yaml`](../src/tram_odometry/config/params.yaml).
[`load_params`](../src/tram_odometry_core/tram_odometry_core/types.py) читает вложенность
`/**.ros__parameters`, требует каждый ключ и отвергает неизвестные ключи и неверные
типы. Ниже перечислены **все** конечные ключи файла на текущем `origin/main`.
Слово «резерв» означает, что ключ задан контрактом, но пока не влияет на выход
`Odometry.step`. Числа следует сверять с YAML: это описание смысла, не второй
источник настроек.

| Ключ | Единица, смысл и текущее использование |
|---|---|
| `frames.map` | Имя локальной системы ENU для `Odometry.header.frame_id`; по умолчанию `map`. Использует ROS-обёртка. |
| `frames.base` | Имя системы вагона для `Odometry.child_frame_id` и `VelocitySensor.header.frame_id`; `base_link`. |
| `input.wheel_speed_scale` | Множитель км/ч → м/с (`1/3,6`), применяется один раз в `Preprocessor._wheel`. |
| `input.stale_timeout_s` | Секунды допустимого молчания тележки; старше этого `SlipDetector.update` ставит доверие 0. |
| `input.max_wheel_accel_mps2` | м/с², предел выброса производной колеса в `Preprocessor._wheel` (`8`); исключения: падение до ровно 0 проходит всегда, скачок с ровно 0 — только если свежая вторая тележка показывает ту же скорость (залипшая тележка, D-031, D-056). Отсекает только сбой датчика; скачки 3–8 м/с² (шум, юз) доходят до `SlipDetector` и разбираются там (D-054). |
| `input.max_wheel_speed_mps` | м/с, `25` (90 км/ч): отсчёт тележки выше — выброс датчика, отбрасывается всегда, включая первый отсчёт потока (#73, D-056). В данных наибольшая скорость колеса — 14,98 м/с по 122 bag (`docs/data.md`, ловушка 1). |
| `input.max_stamp_jump_s` | с, `10`: stamp тележки или контроллера дальше этого впереди самого нового принятого считается сбоем часов и отбрасывается, пока следующий сэмпл не подтвердит скачок (другой поток рядом с тем же stamp или тот же поток, идущий дальше); stamp дальше этого позади гейта своего потока, подтверждённый так же, переставляет гейт назад (#77, D-043). В данных наибольший скачок вперёд — 2,6 с (122 bag), запас ×4. |
| `vehicle.mass_kg` | кг, заглушка 40 000; таблицы модели задают ускорение напрямую, поэтому масса не участвует в расчёте. Сила и масса раздельно по этим измерениям не идентифицируются. |
| `vehicle.wheel_scale_front` | Безразмерная начальная поправка радиуса переднего колеса после перевода единиц; применяется в `Preprocessor._wheel`, относительное отличие тележек затем уточняет фильтр (D-057). |
| `vehicle.wheel_scale_rear` | То же для заднего колеса; общий масштаб пути уточняет привязка к остановкам D-034. |
| `drive.notch_max` | Максимальный модуль команды (`15`), задаёт число строк таблиц `0…15`; форму проверяет `types._validate_drive`, pipeline читает задержанную команду. |
| `drive.speed_grid_mps` | м/с, строго возрастающие узлы скорости от 0 до 16 с 11 узлами, идентифицированы по train в #9 (D-033); `model_accel` линейно интерполирует по ним (D-036). |
| `drive.traction_accel_table` | м/с², неотрицательные модули тягового ускорения, row-major `notch × speed_grid_mps`, нулевая строка из нулей; значения train #9 применяются в `model_accel`. |
| `drive.brake_accel_table` | м/с², неотрицательные модули тормозного ускорения в том же порядке; значения train #9 применяются в `model_accel`. |
| `drive.adhesion_accel_mps2` | м/с², верхняя граница модуля ускорения по сцеплению (`1,60` — максимум таблиц 1,592 с округлением вверх, D-033, D-070); применяется в `model_accel` (D-036); валидируется; расчёт применяет. |
| `drive.traction_power_w_per_kg` | Вт/кг = м²/с³, предел удельной мощности тяги (`8,5`, D-033); применяется в `model_accel` (D-036). Это не измеренный момент двигателя. |
| `drive.response_delay_s` | с, задержка отклика привода: таблицы подогнаны к позиции контроллера `notch(t − 0,3)` (D-033); `pipeline` берёт позицию из кольцевого буфера команд с этой задержкой (D-036). |
| `drive.use_model` | флаг: `true` — `model_accel` вызывается при каждом принятом входе и идёт в прогноз фильтра и детектор; `false` — модель не вызывается (`a_model=0`), фильтр остаётся активным. |
| `resistance.c0` | м/с², постоянная часть эффективного сопротивления Дэвиса, `0,00526` по выбегу train без явной коррекции уклона (D-033); вычитается в `model_accel`. |
| `resistance.c1` | с⁻¹, коэффициент при скорости; используется в формуле сопротивления, сейчас 0. |
| `resistance.c2` | м⁻¹, коэффициент при квадрате скорости; используется в формуле сопротивления, сейчас 0. |
| `filter.rate_hz` | Гц, проектная частота (`40`); фактически нода публикует на каждом принятом входе, отдельного таймера нет. |
| `filter.q_accel` | `(м/с²)²·с`, спектральная плотность белого шума ускорения; вклад в дисперсию скорости за `dt` по контракту равен `q_accel·dt` (D-032). |
| `filter.r_wheel` | `(м/с)²`, дисперсия скорости одной исправной тележки; эффективная дисперсия при `trust > 0` равна `r_wheel/trust` (D-032, D-057). |
| `filter.q_bias` | `(м/с²)²/с`, спектральная плотность случайного хода смещения ускорения (D-032, D-057); значение `0,2` выбрано по train. |
| `filter.initial_bias_var` | `(м/с²)²`, начальная дисперсия смещения ускорения (D-032, D-057); значение `0,25`. |
| `filter.nis_gate` | Безразмерный включительный порог NIS (`9`); по контракту #11 измерение с NIS выше порога отклоняется (D-032). |
| `filter.bias_release_speed_mps` | м/с (`0,5`): ниже неё (или ниже `position.stop_speed_mps`, что больше) при торможении смещение ускорения сбрасывается — торможение не продлевается через v=0 (D-073). |
| `filter.pair_window_s` | с (`0,02`): отсчёты двух тележек не дальше по stamp — одновременная пара; по ней подтверждается остановка (два нуля) и оценивается масштаб (D-073). |
| `filter.departure_slack_mps` | м/с (`0,05`): допуск к `input.max_wheel_accel_mps2·(t − остановка)` — отсчёт не выше считается правдоподобным отъездом (D-073). |
| `filter.departure_var_factor` | безразмерно (`9`, не меньше 1): на правдоподобном отъезде дисперсия скорости не ниже factor·дисперсии измерения, чтобы апостериор торможения не тормозил первое колесо (D-073). |
| `filter.scale_min_trust` | безразмерно (`0,8`, в (0, 1]): пара годится для относительного масштаба, только если доверие обеих тележек не ниже (D-073). |
| `filter.scale_min_speed_mps` | м/с (`2,0`): пара годится для масштаба, только если обе тележки быстрее — на малой скорости дискретизация датчика больше разницы масштабов (D-073). |
| `filter.scale_max_diff_mps` | м/с (`0,5`): расхождение пары больше — это юз, а не масштаб (D-073). |
| `filter.scale_max_rel` | безразмерно (`0,03`, в (0, 1)): предел относительного масштаба тележек ±3 % — вдвое шире разброса колёс между трамваями ±1,5 % (D-073). |
| `filter.scale_gain` | безразмерно (`0,02`, в (0, 1]): шаг экспоненциального сглаживания относительного масштаба на одну пару (D-073). |
| `slip.front_rear_threshold_mps` | м/с, базовый допуск расхождения двух тележек (`0,5`) в `SlipDetector.update`. |
| `slip.model_residual_threshold_mps2` | м/с², рост допуска с `dt` (`1,0`) в `SlipDetector.update`; это порог, а не измеренное ускорение. |
| `slip.noise_accel_mps2` | м/с², скачок тележки: собственное ускорение шага минус модельное больше этого (`3,0`) — вагон так не ездит. На train у исправных тележек p99 = 1,2, p99,9 = 2,3; под шумом stress медиана 3,2 (D-054). |
| `slip.noise_hold_s` | с, сколько скачок считается недавним (`1,0`): противофазные скачки обеих тележек в этом окне — шум, синфазные — юз всего вагона (D-054). |
| `position.map_file` | Имя карты `route.csv` внутри `share/tram_odometry/maps`; `load_route` также читает `stops.csv` рядом, если он есть. |
| `position.use_map` | Логический переключатель карты: `true` — `PathTracker`, `false` — прямая по начальному курсу. |
| `position.join_m` | м, максимальный разрыв для продолжения ветки карты на её конце (`15`). |
| `position.along_drift_frac` | Безразмерная 1σ ошибка вдоль пути на метр после якоря (`0,01`); ковариация растёт с пробегом. |
| `position.cross_std_m` | м, постоянная 1σ поперёк пути (`0,5`) в ковариации `PathTracker.advance`. |
| `position.fix_gate_m` | м, удалённость fix окна от всей карты, после которой fix отклоняется (`50`); защита от выброса GNSS. |
| `position.heading_min_base_m` | м, нижняя граница базы master → rover в окне GNSS (`5`). База короче — курса нет, ветка выставки — ближайшая (D-062; в данных база 11,6–14,6 м). |
| `position.heading_max_base_m` | м, верхняя граница базы master → rover (`20`). База длиннее — выброс rover, курса нет (D-062). |
| `position.base_ahead_m` | м, на сколько `base_link` (ось передней тележки) впереди антенны master по ходу (`9.873`): tf организаторов 27.09, master x = −9,873. Карта, якорь и места остановок — трек master; выход `/result/position` — точка на этом расстоянии дальше по дуге карты (D-076). `0` — выход в точке master, как до D-076. |
| `position.antenna_height_m` | м, высота антенн над `base_link` — точкой касания колеса и рельса (`3.0`): tf организаторов, z = 3,0. Высота выхода = высота карты (антенны) минус это (D-076). |
| `position.side_speed_mps` | м/с, скорость, выше которой трамвай в окне после начала тупиковой боковой ветки считается ушедшим на неё (`5,8`). Боковая ветка — тупик, отходящий от ветки не там, где её продолжение по умолчанию (въезд в депо у западной конечной, ветка 4 от ветки 0). Train, 15–55 м после развилки: на петлю и в конец ветки 0 не быстрее 4,61 м/с, в тупик не медленнее 7,02 м/с; порог — середина (`tools/pathgraph/side_speeds.py`, #138, D-074). |
| `position.side_min_m` | м, начало окна решения по пути после начала боковой ветки (`15`): раньше трамвай ещё не разогнался. |
| `position.side_max_m` | м, конец окна (`55`); кончается до развилки петли, которая в 62 м после начала ветки 4 (D-074). |
| `position.side_overrun_m` | м, путь за тупиком боковой ветки, после которого переход на неё признаётся ошибкой и трамвай возвращается на путь по умолчанию, как будто перехода не было (`30`; в данных трамвай уезжает за конец ветки 4 не больше чем на ~15 м) (D-074). |
| `position.anchor_std_m` | м, начальная 1σ неопределённость положения вдоль пути сразу после GNSS-выставки (`3`); квадрат задаёт начальную дисперсию `PathTracker`. |
| `position.stop_speed_mps` | м/с, порог покоя (`0,3`), используемый `Odometry._on_standstill` для начала отсчёта стоянки. |
| `position.stop_min_s` | с, минимальная длительность стоянки (`5`), после которой однократно предлагается привязка к месту; в окне GNSS она отключена. |
| `position.stop_snap_max_m` | м, максимальное расстояние вдоль дуги до места (`20`); дальше стоянка трактуется как сигнал, путь не корректируется. |
| `position.stop_std_m` | м, 1σ неопределённость места остановки (`2`), задаёт вес взвешенной коррекции `s`. |
| `position.scale_alpha` | Безразмерный вес онлайн-обновления масштаба (`0,3`) по отношению пути карты к пути колёс между двумя стоянками. |
| `position.scale_max_dev` | Безразмерная максимальная поправка масштаба (`0,03`): оценка ограничивается диапазоном `1 ± 3 %`. |
| `position.scale_min_arc_m` | м, минимальная дуга между остановками на одной ветке (`300`), чтобы использовать пару для обновления масштаба. |
| `gnss.init_window_s` | с, разрешённое окно начальной выставки от первого `header.stamp` (`5`); `Odometry._in_window`. |
| `gnss.topic_fix` | Имя входного топика master fix; используется нодой и `Odometry.step`. |
| `gnss.topic_vel` | Имя входного топика master vel; курс запасного режима в `Odometry._on_vel`. |

## Допущения и пределы применимости

- Колёса дают модуль скорости, знак заднего хода не различим. Карта движется по
  выбранной ветке вперёд; на другом маршруте или при неверной ветке ошибка растёт.
- Карта построена офлайн из train, GNSS после окна не используется в оценке.
  Начало ENU — первый fix master со статусом GBAS в окне, иначе первый валидный.
- Рельсовый уклон, радиус колеса, передаточное отношение и момент двигателя
  напрямую не наблюдаются имеющимися входами. `wheel_scale_*` — эмпирические
  поправки, а не измеренный радиус; `mass_kg` пока не участвует в расчёте.
- При молчании обеих тележек скорость прогнозируется из `a_model + bias`;
  `a_model` идёт из модели привода #10 (D-036).
- Ниже 0,5 м/с отрицательное смещение ускорения сбрасывается (D-057):
  торможение нельзя продолжать экстраполировать через неподвижное состояние.
- `filter.rate_hz` не ограничивает частоту фактических публикаций; её надо мерить
  на стенде, как и задержку и память.
