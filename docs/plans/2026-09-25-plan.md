# План: резервная одометрия трамвая, 25–27.09.2026

**Цель:** к 27.09 18:00 в `main` лежит решение, которое проходит стенд жюри (сборка без
сети, `/result/*` ≥ 20 Гц, задержка p99 ≤ 100 мс, ≤ 2 ядра, ≤ 512 МБ) и побеждает бейзлайн на
holdout по скорости и положению. Документы сдачи подтверждены командами. С 18:00 до 23:59 —
только проверка сдачи и питч.

**Архитектура:** ядро `tram_odometry_core` (numpy 1.21, без ROS) → тонкая нода `rclpy` →
`/result/*`. Одно ядро гоняют нода и `tools/eval` (D-001). Положение — по карте маршрута из
GNSS train (D-007), скорость — EKF с моделью привода и адаптивным доверием к тележкам
(D-008, D-009). Контракты — `docs/contracts.md`, данные — `docs/data.md`.

## Как брать работу

- Пакет = GitHub issue с меткой `area:` и строкой «Зависит от #…». Взять — `gh issue edit N
  --add-assignee @me`. Issue с `area:`, которая уже в работе у другого, не брать.
- Пакет можно начинать до готовности зависимостей — на заглушке, с пометкой в PR. Принимать
  — только на реальных модулях в `main`.
- Приёмка модели — число `tools/eval` на holdout против `origin/main` (D-012). Приёмка
  реального времени — стенд `docker/jury-stand.sh`.
- Числа в критериях приёмки ниже — пороги «не хуже бейзлайна» и пороги критерия 4. Абсолютные
  цели по точности появятся после бейзлайна (чекпоинт 0) и записываются в `HANDOFF.md`.

## Фаза 0 — сквозной путь (25.09)

### C1. Контракт v1 в коде — `area:contracts`

`types.py` по `docs/contracts.md` §2: dataclass-типы, `Params`, `load_params(path)` для
`params.yaml`, пустой `pipeline.Odometry` с сигнатурой `step(raw) -> Estimate | None`.
Снять пометку «черновик» с `docs/contracts.md`.

- Приёмка: `pytest`: `load_params(src/tram_odometry/config/params.yaml)` читает все ключи;
  типы импортируются на numpy 1.21 (`bash docker/dev.sh python3 -m pytest`); вердикт
  `reviewer` `merge`, комментарий в #3, #5, #6 со ссылкой на PR (D-018).
- Зависит от: нет. **Первым, ~1 ч.** Размер S.

### P0. Бейзлайн-pipeline — `area:core-pipeline`

Самый тупой рабочий `Odometry.step`: км/ч → м/с, отбросить NaN и stamp из прошлого, скорость —
среднее последних значений двух тележек (или одной, если вторая молчит > `stale_timeout_s`),
путь — интеграл, положение — начальная точка и курс по GNSS в окне выставки + dead reckoning.
Это «первая строка таблицы», которую должны побить модули.

- Приёмка: pytest на синтетике (равномерное движение → путь = v·t; молчащая тележка;
  немонотонный stamp); GNSS после окна не влияет (тест).
- Зависит от: C1. Размер S.

### R1. Нода rclpy + launch — `area:ros`

`odometry_node.py`: параметры из `params.yaml` → `Params`, подписки на три входа + GNSS,
`Odometry.step` на каждое сообщение, публикация `/result/velocity` и `/result/position` по
контракту §1 (stamp входа, frame_id, ковариации), `launch/odometry.launch.py`, entry point
в `setup.py`. Исключение в обработчике не роняет ноду (лог + пропуск сообщения).

- Приёмка: стенд `bash docker/jury-stand.sh 30618_e9a34502` — `/result/*` в записи, stamp
  выходов ⊂ stamp входов, частота ≥ 20 Гц (из записи), нода живёт до конца bag.
- Зависит от: C1 (с P0 — реальный pipeline, до него — заглушка). Размер M.

### E1. tools/eval — `area:eval`

`python -m tram_eval`: чтение bag через `rosbags` в порядке `header.stamp`, обрезка GNSS по
окну, эталон (master fix → ENU от первой точки, фильтр выбросов и статуса; скорость =
`hypot` master vel), сопоставление по stamp с допуском 0,05 с, все метрики `docs/contracts.md`
§4 (along/cross — относительно эталонного трека прогона, пока нет карты), `--split`,
`--bag`, `--compare`, JSON + markdown.

- Приёмка: unit-тесты метрик на синтетических траекториях с известной ошибкой (сдвиг,
  масштаб, задержка); `--split quick` < 2 мин; таблица бейзлайна P0 по holdout →
  `docs/verification/2026-09-25-baseline.md`.
- Зависит от: C1 (для бейзлайна — P0). Размер M–L: если растёт, выделить E1b «bias по режимам».

### S1. Замер реального времени и выбор языка обёртки — `area:stand`

### ID1. Идентификация — `area:ident`

Только train и `no_gnss_train`. Масштаб колеса по трамваю; сопротивление `c0 + c1 v + c2 v²`
по выбегу на нейтрали; `a_drive(notch, v)` тяги и торможения вне проскальзывания; задержка
отклика привода на смену позиции; шумы тележек. Числа → `params.yaml`, графики →
`notebooks/identification/`, отчёт с командами.

- Приёмка: на train, интегрирование модели от реальной скорости на окнах 10 с даёт RMSE
  скорости ≤ порога, записанного в отчёте, и лучше модели «a = 0»; графики a(notch, v) в PR.
- Зависит от: нет (читает bag сам или через E1). **Можно начать 25.09.** Размер M–L:
  разрезать на ID1a (масштаб + сопротивление) и ID1b (тяга/торможение), если берут двое.

### DY1. Модель привода и продольной динамики — `area:core-dynamics`

`model_accel(notch, v, params)`: интерполяция таблиц ID1, ограничения (сцепление, мощность),
сопротивление; задержка привода — через состояние в pipeline или PR контракта.

- Приёмка: unit-тесты (нейтраль → только сопротивление; монотонность по позиции тяги;
  непрерывность по v); метрика ID1 воспроизводится из ядра.
- Зависит от: C1, ID1 (до него — грубые параметры). Размер S–M.

### ES1. EKF скорости — `area:core-estimator`

Состояние: скорость, ускорение/смещение модели, масштабы колёс. Прогноз — `a_model`,
измерения — тележки с доверием от SL1 и gating по инновации; NIS в диагностику eval.

- Приёмка: holdout speed RMSE и |bias| по режимам не хуже P0 и лучше хотя бы по одной
  главной; stress «дыра 70 с одной тележки» без расходимости.
- Зависит от: C1, DY1 (до него — `a_model = 0`), SL1 (до него — доверие 1). Размер M.

### SL1. Проскальзывание и отказ тележки — `area:core-slip`

Признаки из `task.md`: расхождение тележек, ускорение колеса против модели, высокая тяга
при малой производной, отрицательное рассогласование при торможении, дисперсия. Выход —
`SlipState` (доверие 0..1, флаги, оценка сцепления).

- Приёмка: на 6 bag 30639 с расхождением флаг покрывает ≥ 90 % интервалов |Δ| > 1 км/ч;
  ложные флаги ≤ 1 % времени движения на train 30618; stress «всплеск одной тележки»:
  пик ошибки скорости ниже, чем у P0.
- Зависит от: C1. Размер M.

### PO1. Положение по карте — `area:core-position`

Выставка в окне GNSS: точка на карте (ветка и `s0`), направление (база master→rover или

- Приёмка: holdout along-track RMSE и drift % лучше P0; cross-track медиана ≤ 2 м.

### E2. Стресс-генератор — `area:eval`

- Приёмка: тесты ноды в контейнере (`colcon test`); stress-bag на стенде — нода живёт,
