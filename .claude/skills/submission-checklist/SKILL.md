# Чек-лист сдачи

Источник — `task.md` («Критерии», «Обязательные артефакты») и README данных (`docs/data.md`,
раздел «Контракт жюри»). Каждый пункт проверяется **командой или файлом**. Результат —
таблица `пункт | ✅/❌/⚠️ | доказательство | что сделать`. Ничего не исправлять молча:
сначала отчёт, исправления — отдельными PR.

## 0. Git

```bash
git fetch --prune && git status -sb
git log --oneline origin/main -1          # commit сдачи — в origin/main
gh pr list --state open                   # открытые PR с нужной для сдачи работой — ❌
```

## 1. Технические пороги — на стенде жюри, commit сдачи

```bash
git clone <origin> /tmp/sub && cd /tmp/sub        # чистый клон, не рабочая копия
bash docker/jury-stand.sh <holdout bag> 1.0       # сеть выключена, 2 CPU, 512 МБ
```

- [ ] `colcon build` без сети — все пакеты (`build.log`), включая `tram_vehicle_msgs`
- [ ] нода стартует по launch из README без ручных шагов и не падает до конца bag (`node.log`)
- [ ] `/result/velocity`: `tram_vehicle_msgs/msg/VelocitySensor`, скорость в `velocity`, **м/с**
- [ ] `/result/position`: `nav_msgs/msg/Odometry`, позиция в `pose.pose.position` (м, локальная
      система, согласованная с эталоном), `twist.twist.linear.x` — продольная скорость,
      ковариации заполнены
- [ ] `header.stamp` обоих = время входа из bag (не wall clock, не ноль); `frame_id` заполнен
- [ ] частота каждого `/result/*` ≥ 10 Гц (цель 20–50) — из записи, не из кода
- [ ] задержка вход → выход p99 ≤ 100 мс, max ≤ 250 мс — из замера стенда
- [ ] CPU ≤ 200 % (2 ядра), пиковый RSS ≤ 512 МБ, RSS не растёт на длинном bag (≥ 20 мин)
- [ ] GNSS в контуре только первые `gnss.init_window_s` с: `grep -rn gnss src/tram_odometry*/`
      + прогон `tools/eval` с обрезкой GNSS даёт те же выходы, что без неё после окна
- [ ] нет данных «из будущего»: публикация онлайн на каждом входе, без пакетной обработки

## 2. Шесть артефактов формы (ссылки на файлы в репозитории)

| # | Артефакт (task.md) | Где | Проверка |
|---|---|---|---|
| 1 | Пакеты ROS 2 Humble, `colcon build`, подписка на входы, `/result/*` | `src/` | п. 1 выше |
| 2 | Инструкция жюри: как проиграть bag, какие топики, где логи, метрики, задержка | `README.md` | выполнить каждую команду README в чистом клоне |
| 3 | Модель: уравнения, структура, входы/выходы, ускорение, момент → скорость | `docs/model.md` | уравнения совпадают с кодом ядра (имена функций в тексте) |
| 4 | Допущения, ограничения, параметры (начальная позиция, масса, радиус колеса, сопротивление, пороги проскальзывания, фильтр) | `docs/parameters.md` | каждый ключ `params.yaml` описан, лишних нет: сравнить списки |
| 5 | Точность и быстродействие: методика с GNSS-эталоном, таблицы, графики, замеры задержки/частоты/ресурсов | `docs/accuracy.md` + `docs/verification/` | числа совпадают с последним прогоном `evaluator` на commit сдачи |
| 6 | Ограничения и план развития | `docs/roadmap.md` | есть |

### Форма «Загрузка решения» — поля дословно (все обязательны, в каждое — ссылка)

1. Ссылка на пакет(ы) ROS 2 Humble (C++ и/или Python), собираемые colcon build, с подпиской на входные топики и публикацией /result/velocity и /result/position.
2. Ссылка на инструкцию для жюри по проверке: как воспроизвести rosbag, какие топики ожидать на выходе, как посмотреть логи/метрики и задержку.
3. Описание математической модели: уравнения, структура, входные/выходные переменные, способ оценки ускорения и перехода от момента к скорости.
4. Перечень допущений и ограничений, а также описание конфигурируемых параметров (начальная позиция, масса, радиус колеса, коэффициенты сопротивления, пороги проскальзывания, параметры фильтров и т.д.).
5. Сведения о точности и быстродействии: методика сравнения с GNSS-эталоном, таблицы ошибок, графики (при наличии), замеры задержки/частоты/ресурсов.
6. Описание ограничений решения и плана развития после хакатона.

- [ ] **генеральная репетиция жюри:** человек, не писавший ноду, на чистой машине/контейнере
      проходит README дословно (clone → colcon build без сети → play bag → `/result/*`),
      без подсказок и без файлов из рабочей копии. Главный риск сдачи — «у организаторов
      не запустилось», а не точность модели.

- [ ] ссылки на файлы — на ветку `main` / тег сдачи, открываются у человека без доступа?
      (репозиторий приватный: форма жюри требует ссылок — решить открыть доступ или
      приложить экспорт; см. `HANDOFF.md`, блокеры)
