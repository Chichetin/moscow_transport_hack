Ты делаешь одну issue. Правила — `CLAUDE.md` (загружен), Git — `GIT.md`, контракты —
`docs/contracts.md`, карта областей — `docs/project-structure.md`.

Бриф содержит номер issue и абсолютный путь worktree. Остальное — из самой issue
(`gh issue view <N>`): критерий приёмки, `area:`, «Зависит от #…». Чего нет ни там, ни
там — не придумываешь, спрашиваешь.

## Где ты работаешь

Все изменения — только в worktree из брифа, ветка `worktree-<N>-<тема>`:

```bash
git -C <worktree> status -sb      # не main
gh issue view <N> --json assignees -q '.assignees[].login'   # issue на участнике, не пустая
```

Каждая команда — `cd <worktree> && …`; Read/Edit/Write — по абсолютным путям внутри
worktree. `git add` — только свои пути.

## Порядок

1. Прочитать issue, `docs/contracts.md` в части, которую используешь, код соседей по
   контракту (не по внутренностям).
2. Тест поведения → красный → код → зелёный. Ядро тестируется без ROS:
   `.venv/bin/python -m pytest`. Код ядра обязан работать на numpy 1.21 (ROS Humble):
   без `np.trapezoid`, `np.random.Generator.spawn` и прочего нового API — проверка
   `bash docker/dev.sh python3 -m pytest`.
3. Мутационная проверка для кода с расчётом: сломать 3–5 мест (знак, единицы км/ч↔м/с,
   граница порога, пропущенная ветка) — тесты должны краснеть. Число мутаций и выживших — в отчёт.
4. Метрика: `tools/eval` на holdout для ветки и для `origin/main` (команды — `tools/eval/README.md`).
   Ухудшение главных метрик holdout — не PR, а доклад (CLAUDE.md, «Спор решает метрика»).
   Пока `tools/eval` нет в main — так и пишешь в PR: «метрика не считалась: eval не влит».
5. Документы в том же PR: решение — `D-<N>` в `docs/decisions.md`; закрытый пункт условий —
   строка в `docs/tz-compliance.md`; новый параметр — комментарий в `params.yaml` с единицами.
6. `git fetch --prune && git merge origin/main`, тесты заново, коммит, push, PR:

   ```bash
   git push -u origin HEAD
   gh pr create --base main --title "<area>: <что сделано>" --body-file <файл с шаблоном PR>
   ```

   Шаблон — `.github/pull_request_template.md`; `Closes #<N>` обязателен.

## Границы

- Контракт (`docs/contracts.md`, `types.py`, `params.yaml` — имена/единицы, топики, формат
  метрик) не меняешь. Нужен — остановись: какое поле, зачем, кто потребители
  (`grep -rn` по `src/ tools/`). Контракт меняет основная сессия отдельным PR (D-018).
- Новую зависимость не добавляешь: в рантайме только apt Humble, в tools — через `requirements-dev.txt`
  отдельным PR.
- Файлы вне `area:` своей issue не правишь; соседний код не переформатируешь.
- GNSS в основном контуре — только первые `gnss.init_window_s` секунд. Использовать позже —
  дисквалификация (task.md, README данных).

## Когда остановиться

- `check-upstream.sh` показал коммит, меняющий твой контракт или ту же область.
- Зависимость из «Зависит от #…» ещё не в main — делай на заглушке, в PR пометка
  «принято на заглушке, не на реальном модуле».
- Тест или метрика не сходятся после двух честных попыток — не ослабляй проверку, опиши.

## Отчёт

```
Issue: #<N> — <название>; ветка / PR / commit
Сделано: 2–5 строк
Проверки: pytest N/N; numpy 1.21 в контейнере ок/нет; colcon build ок/нет
Метрики holdout (было → стало): speed RMSE, along-track RMSE, drift % | не считались: почему
Мутации: N сделано, M выжило, чем закрыто
Решения: D-…; tz-compliance: строки
Нужно решение основной сессии: контракт / зависимость / конфликт / нет
```
